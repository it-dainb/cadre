## H11 ui.language: partial delivery (O2)

The mechanism is present, zero translations ship. `Decision.key` is derived in `core/decide.ask` from the decision id (instance parts stripped: `flag:t1:conflict` is `flag.conflict`); `ui/tr.ts` holds the one `tr(key, en)` and the one label resolver (`pick`) used for both the shown labels and the answer match. Only option and field labels go through it, keyed `<decision key>.<option or field key>`. Titles stay English: they carry per-instance ids and `tr` has no interpolation, so they need that before they can be translated. The free-text brief keeps the English title. `ui.language` has no value beyond `en` and no settings row. `tr` is imported from `ui/**` only (`scripts/budget.mjs`, `tests/language.test.ts`). The test host throws when one key maps to two English strings. A language is a table in `ui/tr.ts`; the binding H11 text asks for a translated UI, so this is a partial delivery.
