# ADR 0030: 1.0 hardening

Status: in progress. Sections are added by the slice that delivers them.

## H11 ui.language: partial delivery (O2)

The mechanism is present, zero translations ship. `Decision.key` is derived in `core/decide.ask` from the decision id (instance parts stripped: `flag:t1:conflict` is `flag.conflict`); `ui/tr.ts` holds the one `tr(key, en)` and the one label resolver (`pick`) used for both the shown labels and the answer match. Only option and field labels go through it, keyed `<decision key>.<option or field key>`. Titles stay English: they carry per-instance ids and `tr` has no interpolation, so they need that before they can be translated. The free-text brief keeps the English title. `ui.language` has no value beyond `en` and no settings row. `tr` is imported from `ui/**` only (`scripts/budget.mjs`, `tests/language.test.ts`). The test host throws when one key maps to two English strings. A language is a table in `ui/tr.ts`; the binding H11 text asks for a translated UI, so this is a partial delivery.

## Doctor coverage (slice 7)

Coverage is by produced rows, a deviation from the §3.5 wording ("every replay row has a Doctor line"): replay rows are lifecycle races, not machine facts. `tests/doctor-coverage.test.ts` runs `machine()` and `doctor()` over fixture hosts and asserts that every non-ok row's fix text appears in `docs/troubleshooting.md`; no call-site count is claimed. Four informational rows (a newer Claude Code build, the exit-tools tested-up-to note, an unavailable custom role, tools Claude Code injected) carry no fix of their own, because adding one would change text the setup checklist hands to Claude; the test lists them and requires their wording in the doc instead. The docs are frozen into `tests/fixtures/budget.generated.ts` by `scripts/budget.mjs` (the kit has no fs), with the list of relative README and guide links that do not resolve.
