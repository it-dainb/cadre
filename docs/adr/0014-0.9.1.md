# ADR 0014: 0.9.1

## Task store in .cadre/store
- Every bd call carries `BEADS_DIR=<repo>/.cadre/store` (`adapters/beads/layout.ts` `dirOf`; `Bd` adds it to the env). Probed with real bd 1.3.1: `bd init` under BEADS_DIR puts the store there and writes no `.beads` at the root; it needs `.cadre/` to exist, and drops `.cadre/store.gate.lock` beside the store (both excluded in `.git/info/exclude`; bd also writes a root `.gitignore`, as before).
- Legacy: no `.cadre/store` but a `.beads` → no BEADS_DIR, bd finds `.beads` itself. Never moved automatically: doctor shows a row and a card (`init:92`, answered through `setup confirm`); the move (`moveStore`) refuses while a task is active or in review, `mv`, re-probes, rolls back on failure, then adds the exclude lines.
- Fence and effect check need no change: `.cadre/` is already protected (`PROTECTED`, `STATUS` exclude, L2 denyWrite on the repo). `.beads` stays listed for legacy repos.
- Tests: `tests/store-layout.test.ts`; real bd: `tests/dev/store-dir.mjs`.
