# ADR 0011: lanes (`/cadre <goal>`: ask · lite · full) and the five typed forms

Status: accepted (0.8.0). User decisions, 2026-10-12. Deviates from DESIGN §5.3 (the typed subcommand table) and fills the roadmap's "quick lane" (DESIGN §16) in a different shape.

## Why
Every request went through the full loop: a plan, a mission-sized contract, scenarios for every task, tester → red → worker → green → reviewer. A one-line fix cost as much ceremony as a feature, and a question needed no plan at all. The typed surface also had grown to fourteen subcommands that the cards had made redundant, and a typo of one of them would now start a plan.

## Decision
**Typed surface: five forms only.** `/cadre` (the pane: the card when a decision waits, else the epic) · `/cadre <goal>` · `/cadre setup` · `/cadre init` · `/cadre doctor`. An exact old subcommand word (`approve reject resolve restore release drive config sync adapter status open confirm cancel resume`, plus `lane`, `goal`, and `setup|init|doctor` with arguments) answers one line, `that's a button now: press 1 on the band or run /cadre`, and runs nothing, so a typo never starts a plan. The match is on the first word, lowercase, exact; `Setup CI for this repo` is a goal. The dispatcher commands stay: the card's buttons and the pane's tabs run them as origin press (ADR 0008, 0012). `commands/cadre.parse` is the parser; `route` is the one router for presses.

**`/cadre <goal>`** (composer origin only, active repo only: dormant answers `cadre is off in this repo · run /cadre init`). cadre queues one brief for main: the goal, then `guides/goal.md` inlined. Main cannot Read the plugin folder outside a setup/init lease (the plugin-store read fence, ADR 0010), so the guide rides in the brief instead of being pointed at. The 0.7.0 mechanism carries it: `$.prompt.submit` is refused from a command frame, so the brief waits in `ui.goal` and `commands/agentrun.pump` (the 5 s timer) sends it once. The guide: classify with a one-line reason, then
- **ask** (question, investigation, spike: nothing changes): spawn one Agent with the question. The asks contract (ADR 0010) tracks it and main gets the answer card. No plan, no branch.
- **lite** (one small clear change): ONE `TaskCreate` with `{"kind":"plan","lane":"lite","reason","type","changelog"[,"repro":true]}`. `native/tasks` drafts the plan and its one task from that call. Completeness = title + description + changelog decision (no scenarios, contract or package; the package defaults to `.`).
- **full** (feature, several tasks, public API change, risky): the existing plan drafting with `"lane":"full"`.

**Deterministic override** (`core/lanes.laneOf`, pure): lane → full when any draft is `breaking`, labeled or scoped `security`, declares a contract symbol `new|changed` (a contract present and not `{none}`), or the plan has ≥3 tasks. Added beyond the brief: **lite has exactly one task** (a second task moves it to full), because two lite tasks have no scenarios to order or review them by. An **ask** plan holding a code-changing task becomes lite (one task) or full. Main picking full is never overridden down. `relane` runs before every draft redraw (native/tasks): the effective lane goes on `board.plan` (`lane`, `laneReason` = main's or the human's reason, `laneOverride` = why the override moved it) and onto each draft as `cadre.lane` (`lite`, `lite+tdd`, or empty). Main's pick and reason live on the epic (`cadre.lane`, `cadre.laneReason`), so the override is recomputed from beads every time.

**Lite pipeline** (`registry.pipeOf(reg)(type, lane)`): `lite` drops tester/red where a worker writes the change (bug, feature → worker → green → reviewer → merge; docs → worker → reviewer → merge; `test` keeps its tester). `lite+tdd` (a `bug` with `"repro": true`) keeps the type's full pipeline: tester → red → worker → green → reviewer → merge. `SnapTask.lane` carries it to the machine, admission, close and tdd. Same guards, worktree, review bound to a commit, and squash; the full lane is unchanged.

**The card** (drawn by `core/dispatch.redraw`, ADR 0008): its first line is `laneLine` (`lite · 1 task · fix · <reason>`; an override reads `full · 2 tasks · lite is one task → full · <reason>`), part of the content hash. **[l] Lane → <next>** (`laneOption`) cycles ask → lite → full → ask, skipping a lane the override would refuse, and the label names the target. The press runs `lane <planId>` (press or dialog only), which re-classifies a first draft only: → lite/full sets the epic's lane to the new one with reason "changed by you", re-lanes the drafts and redraws (→ full also briefs main to add the full fields; the card's missing list says what is left). → ask drops the draft plan (a decision record) and briefs main to spawn the explorer with the plan's title and description. **One-click approval for lite** (user decision): the lite card is the same Approve press; nothing starts by itself.

## Consequences
- `/cadre status`, `open`, `config show` and friends are no longer typed. `status` is gone (it had no button); the model-visible board line is main's per-turn context line (DESIGN 4.5).
- Strings that still say `/cadre resolve …` in denials and toasts outside this ADR's files describe a button now; they are left for the card owners.
- A goal typed while a plan is open is passed to main anyway: an ask works at any time; a new plan is refused by `TaskCreate` with "plan … is still draft", and the guide tells main to tell the user.
- Kit: `tests/lanes.test.ts` (parser, dormant and origin refusals, the brief and the timer, wording lint of the guide and the lane briefs, the override table, lite pipeline and completeness, the bug TDD path, one-call lite drafting, the lane line, Change lane both ways); `tests/dispatch-cadre.test.ts` (typed hints, presses).
