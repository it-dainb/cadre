# cadre: module contracts (wave 1)

Read this before touching a module. Governing docs: `docs/design/DESIGN.md` (v2.5), `docs/design/UI-DESIGN.md`. Section refs `§n` are DESIGN's.
**Rules.** Static relative imports only; no npm/Node/zod. `$` exists only in `hooks/register.ts`; every other module gets a per-hook `Host` (below). Never keep a Host in a module variable. Slots are filled **in place**: keep the exported name and signature, replace the body. Do not edit `register.ts` except to add a Host member (append-only) or a new slot; a new `on()` needs a distinct matcher if its event is already registered (same event twice without a matcher is a load error).
**Gates before commit:** `node scripts/budget.mjs` (regenerates `tests/fixtures/budget.generated.ts`; the kit has no fs) → `claude plugin validate --strict .` → `claude plugin test .` (pin: `~/.local/share/claude/versions/2.1.295`).
**Placeholder rule:** a slot not yet owned is a pass-through (`return next(e)`); its file starts with `// OWNER: wave-N <area>`. Remove the header line when you fill it.

## Contract types: `types/index.d.ts` (self-contained: the validator refuses imports there)
`Category` · `Role` · `Actor` · `Severity` · `Kind` · `SnapDepType` · `PlanState` · `SnapTask` · `Plan` · `Snapshot` · `EventType` · `CadreEvent` · `EventRing` · `Secret` · `Binding` · `GitState` · `Cell<T>` · `Host` · `Hook`.
- `PluginState.cadre = { board: Snapshot, events: EventRing, secret: Secret, ui: Record<string,unknown>, git: GitState, bind: Record<agentId, Binding> }`. `bind` is an addition to the brief's list (binding table, §4.4.4); nonce, init nonce and session token live in `secret` (UI-private, never in a view or event).
- `Host` (built by `host($)` in register.ts, one per hook entry): `now()` · `rand(bytes=16)` hex · cells `board|events|secret|ui|git|bind` each `{read(), update(fn)}` (`update` = CAS with retry: **fn must be pure**) · `store {get,set,del}` ($.store, per-user keys) · `env()` (the four `CADRE_*`) · `readText(path)` (null if missing) · `log(text)` · `toast(text)` (local, zero tokens) · `options {strictness?}`.
- `Hook = (h: Host, e: any, next: (e:any)=>any) => any`.

**Machine semantics (decided here).** A task's `step` is the current pipeline step; its category follows the step (`tester red worker green explorer report` → `active`; `reviewer merge` → `review`). `claim`: `todo→active`, `step = t.step || pipeline[0]` (a released task resumes at its step). `advance`: `active` only, to the next pipeline step (so `red`/`green` are real, mod-run phases). `verdict pass` (`review·reviewer`) → step `merge` (= review✓); `changes` → `active` at the last `worker`/`tester` before `reviewer`. `close`: `review·merge` or spike `active·report` → `done`. `block`: from `active|review`; `unblock` returns to the category of the kept step. `release`: `active|review|blocked → todo`, owner cleared, step kept. `skip` (todo, conditional-blocks upstream closed `done`): `→ cancelled` + `task.skipped`. Illegal moves return `{ok:false, error}` (a deny reason); nothing is committed or emitted.

## How to ask the human (ADR 0008, 0012): one record, one dialog
Every phase that needs a human decision does **only** this; it never draws UI.
```ts
import { ask, settle } from '../core/decide'
await ask(h, {                        // add, or replace under the same id (keeps its queue place)
  id: `deploy:${n}`, kind: 'deploy',  // id is the identity (a dialog pops once per id); kind is free text (the UI never switches on it, save the tag from `crit`/kind 'flag')
  title: 'deploy build 7 to staging?', short: 'deploy build 7',        // the dialog's first line and the band row (short = narrow form, optional)
  lines: ['3 services restart', 'rollback is automatic'],              // body: the dialog shows at most 6 lines (each fact once); the pane's Needs you shows all
  hash: fnv1a64(content),             // CONTENT hash (no secret): an answer to an older hash is refused "it changed; review again" and the dialog re-asks
  options: [{ key: 'd', label: 'Deploy', verb: 'approve', run: 'deploy now' },              // run = a dispatcher command, run as origin dialog
            { key: 'w', label: 'Wait', verb: 'change' }],                                   // no run: not offered (with < 2 runnable options the dialog adds "Not now")
  change: 'deploy later: ',           // optional: the prefix main gets with the dialog's typed text (default `About "<title>": `)
  tab: 'epic', sel: 'a2', crit: false, quiet: false,   // optional: tab with the full detail (enter on the row) · task to select · CRIT · never pops by itself
})                                    // the dialog (ui/index.answerDialog) is the only answer (ADR 0012)
await settle(h, `deploy:${n}`)        // when answered: removes the decision
```
**Fields (typed input).** `fields: [{key, label, value?}]` are asked one by one in the dialog before the options (`Keep <value>` / `Cancel`, or the typed text is the value). An option's `run` gets them where it says `{fields}`, as one `k=v` argv element each (spaces kept, no shell). Validate in the command; on refusal ask again with `error: '<why>'` (a new hash): the dialog re-asks with the error on top.
**Resume contract (ADR 0009; init and setup no longer use it since ADR 0010, the mechanism stays).** A step blocked on something only the human can supply never fails and never makes them start over. It records what it needs, asks with fields, and the submit command applies the input (argv only) and re-runs the SAME step. Needs that require dialogue go to main instead (below).
Work only Claude can do (setup, init) is not a decision: `commands/agentrun` hands main a brief and re-checks at each main turn end (ADR 0010). Gathering input with AskUserQuestion is not approving a gate.
- **Lives in** `board.decisions` (human view; `modelView` drops it; no codes). Order = oldest first; `1` answers the oldest.
- **The dialog** (`ui/index.answerDialog(h, id?)`): title + ≤ 6 lines; options = the runnable ones (≤ 4) + "Not now" when fewer than 2; the engine's "Type something" = a change request queued to main (`core/lanes.queueBrief`). The answer goes to `Host.answer(id, key, hash, vals)` = `commands/cadre.decide` = `core/dispatch.answer(h, id, key, hash, route, vals)`: decision gone, hash differs or key unknown → `refused: it changed; review again` and nothing runs (the dialog re-asks a changed decision, ≤ 3 rounds); else `run` goes through `dispatch` as origin `dialog`. A gate command lists itself in `gated` (core/dispatch); a plain command (like `deploy`) just works. Dismissed / `-p`: nothing decided.
- **No nagging** (`ui/index.autoAsk`): a new id pops its dialog once (empty composer, no dialog of ours up; ids kept in `cadre.ui.shown`); later only `1` (band `att` Button, the pane's Needs you) opens it.
- **The pane** (`ui/v2/board`): read-only Needs you (`needsFull` on the Board, `needsOne` on the other tabs, the band line in `ui/v2/band`). No option Buttons.
- **Already asking:** plan approval (`dispatch.redraw`, settled by approve/reject; approve queues the "Plan <id> is approved" brief), gates (`gateDraw`/`approveGate`), the setup/init checklist (`run:<kind>`, quiet while Claude works), init's safety settings (`init:5`), sync add (`initPropose`), Settings edits (`cfg:<key>`, one field), every flag (`events.emit` on `flag.raised`, settled on `flag.resolved`; `tdd.specChange` asks first with the reason), release (`integrate.propose`).
- **Adding a kind** = one `ask` and one `settle` in the phase, plus the command the option runs. `tests/decisions.test.ts` proves it with a made-up `deploy` kind (band row, Needs you, dialog) and zero UI code.
- **Survives /clear:** decisions live on the board, so `core/session.rehydrate` re-asks what durable state says is owed: a draft plan (`redraw`) or an open gate (`gateDraw`, first: it shares the approval slot), spec_change tasks (from `cadre.blocked`/`cadre.specChange` in the store, with the reason), plan-level flags (from the pointer), git flags (`cadre.git`), and a landed epic's release (`integrate.propose`). Pending init/setup/sync-add proposals are **dropped** (their code and diff are per session): run the command again. Other task flags are not durable, so they are not re-asked.
- **`core/lessons`** (ADR 0028): `note(h, kind, ref, text, at)` an input with a durable key (secrets scrubbed, ≤200 / 24 KB); `pass(h, idle)` one `h.model.complete` on `lessons.model` (CAS pass cap, evidence checked against the batch, promotion to `~/.claude/cadre/lessons.json`, decay); `feed(h, taskId, paths)` the brief's lessons block (≤5, ≤1.5 KB, `modelText('lesson')`); `rows`/`prune` for the Lessons tab. Events: `decision.answered`, `config.changed`, `task.retried`, `task.cancelled`, `amend.recorded`. `Host.model.complete` is the side-model call (`$.model.complete`, never rejects on a provider error). Config: `lessons.*` (8 REG rows).
