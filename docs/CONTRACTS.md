# cadre: module contracts (wave 1)

Read this before touching a module. Governing docs: `docs/design/DESIGN.md` (v2.5), `docs/design/UI-DESIGN.md`. Section refs `§n` are DESIGN's.
**Rules.** Static relative imports only; no npm/Node/zod. `$` exists only in `hooks/register.ts`; every other module gets a per-hook `Host` (below). Never keep a Host in a module variable. Slots are filled **in place**: keep the exported name and signature, replace the body. Do not edit `register.ts` except to add a Host member (append-only) or a new slot; a new `on()` needs a distinct matcher if its event is already registered (same event twice without a matcher is a load error).
**Gates before commit:** `node scripts/budget.mjs` (regenerates `tests/fixtures/budget.generated.ts`; the kit has no fs) → `claude plugin validate --strict .` → `claude plugin test .` (pin: `~/.local/share/claude/versions/2.1.295`).
**Placeholder rule:** a slot not yet owned is a pass-through (`return next(e)`); its file starts with `// OWNER: wave-N <area>`. Remove the header line when you fill it.

`Category` · `Role` · `Actor` · `Severity` · `Kind` · `SnapDepType` · `PlanState` · `SnapTask` · `Plan` · `Snapshot` · `EventType` · `CadreEvent` · `EventRing` · `Secret` · `Binding` · `GitState` · `Cell<T>` · `Host` · `Hook`.
- `PluginState.cadre = { board: Snapshot, events: EventRing, secret: Secret, ui: Record<string,unknown>, git: GitState, bind: Record<agentId, Binding> }`. `bind` is an addition to the brief's list (binding table, §4.4.4); nonce, init nonce and session token live in `secret` (UI-private, never in a view or event).
- `Host` (built by `host($)` in register.ts, one per hook entry): `now()` · `rand(bytes=16)` hex · cells `board|events|secret|ui|git|bind` each `{read(), update(fn)}` (`update` = CAS with retry: **fn must be pure**) · `store {get,set,del}` ($.store, per-user keys) · `env()` (the four `CADRE_*`) · `readText(path)` (null if missing) · `log(text)` · `toast(text)` (local, zero tokens) · `options {strictness?}`.
- `Hook = (h: Host, e: any, next: (e:any)=>any) => any`.

**Machine semantics (decided here).** A task's `step` is the current pipeline step; its category follows the step (`tester red worker green explorer report` → `active`; `reviewer merge` → `review`). `claim`: `todo→active`, `step = t.step || pipeline[0]` (a released task resumes at its step). `advance`: `active` only, to the next pipeline step (so `red`/`green` are real, mod-run phases). `verdict pass` (`review·reviewer`) → step `merge` (= review✓); `changes` → `active` at the last `worker`/`tester` before `reviewer`. `close`: `review·merge` or spike `active·report` → `done`. `block`: from `active|review`; `unblock` returns to the category of the kept step. `release`: `active|review|blocked → todo`, owner cleared, step kept. `skip` (todo, conditional-blocks upstream closed `done`): `→ cancelled` + `task.skipped`. Illegal moves return `{ok:false, error}` (a deny reason); nothing is committed or emitted.

## Config: `config/`
`defaults()` → `Config` (§12 defaults, fresh object) · `classOf(path) => 'S'|'U'|'O'` (longest dotted prefix) · `tighten(path, base, val)` · `merge(base, layer, trust, diag)` · `resolve(layers: {name, trust:'user'|'repo', value}[]) => {config, diagnostics}` (pure; layers lowest first) · `envLayer(env)` · `load(h, {home, root, repoKey}) => Promise<{config, diagnostics}>` (userConfig → `~/.claude/cadre.json` → its `repos[repoKey]` section → repo `.cadre/config.json` → env).
Repo layer: S keys tighten only (bool → strict value, enum → stricter, list → intersection; `packages[].knownRed` kept only if the user layer granted it for that root); U keys ignored; O keys set. Bad key/type/layer → dropped + diagnostic. ## How to ask the human (ADR 0008): one record, one renderer, one press path
Every phase that needs a human decision does **only** this; it never draws UI.
```ts
import { ask, settle } from '../core/decide'
await ask(h, {                        // add, or replace under the same id (keeps its queue place)
  id: `deploy:${n}`, kind: 'deploy',  // id is the identity; kind is free text (the UI never switches on it, save the [WARN]/[CRIT] tag from `crit`/kind 'flag')
  title: 'deploy build 7 to staging?', short: 'deploy build 7',        // band row (short = narrow form, optional)
  lines: ['3 services restart', 'rollback is automatic'],              // the card's description, plain strings, wrapped by the UI
  hash: fnv1a64(content),             // CONTENT hash (no secret): a press drawn with an older hash is refused "it changed; review again"
  options: [{ key: 'd', label: 'Deploy', verb: 'approve', run: 'deploy now {code}' },       // run = a dispatcher command, run as origin press
            { key: 'w', label: 'Wait', verb: 'change', fill: 'deploy later: ' }],           // fill = loaded into an EMPTY composer instead (nothing runs)
  fallback: '/cadre deploy now {code}',   // typed line for surfaces where nothing draws (VS Code, -p); shown on the band only when it holds {code}
  tab: 'epic', sel: 'a2', crit: false,    // optional UI hints: pane tab behind the card · task to select · [CRIT] tag
}, code)                              // code (optional): what `{code}` expands to; stored in cadre.secret.dcode, never on the board
await settle(h, `deploy:${n}`)        // when answered (also by the typed command): removes the decision and its code
```
**Fields (typed input).** `fields: [{key, label, value?}]` puts one Input per field on the card (prefilled with `value`; typed values live in `cadre.ui.fields[<id>]`; Tab moves, Enter submits the first option). An option's `run` gets them where it says `{fields}`, as one `k=v` argv element each (spaces kept, no shell). The typed fallback quotes them: `/cadre init resume 1 name="Ann Lee" email="a@b.c"` (`commands/cadre.argsOf`). Validate in the command; on refusal ask again with `error: '<why>'` and the typed values as `value`, so nothing typed is lost.
**Resume contract (ADR 0009; init and setup no longer use it since ADR 0010, the mechanism stays).** A step blocked on something only the human can supply never fails and never makes them start over. It records what it needs (`ui['init.blocked'] = {stage, need: {reason, fields}, sig}`), asks with fields, and the submit command (`init resume <n> {fields}`) applies the input (argv only) and re-runs the SAME step; the normal flow then continues (auto-advance). A confirmed diff is not re-confirmed: resume checks that the diff signature still matches, else it re-shows. Setup's form: the identity act takes its values from `setup confirm {code} {fields}`; refused input keeps the code. Needs that require dialogue go to main instead (below).
Work only Claude can do (setup, init) is not a decision: `commands/agentrun` hands main a brief and re-checks at each main turn end (ADR 0010). Gathering input with AskUserQuestion is not approving a gate.
- **Lives in** `board.decisions` (human view; `modelView` drops it; no code ever on the board) and `secret.dcode[id]`. Order = oldest first; the card shows "n of m" with `n`/`p`. Option keys: one lowercase letter, not `n`/`p`.
- **Press** (`Host.press(id, key, hash)` = `commands/cadre.press`): decision gone, hash differs or key unknown → `refused: it changed; review again` and nothing runs; else `run` (with `{code}` from the secret) goes through `dispatch` as origin `{kind:'press'}`, which `isHuman` accepts. A command that must be human-only still lists itself in `needsHuman`; a plain command (like `deploy`) just works. The command's own checks (code re-check, burn on use) are unchanged, so the typed path and the press share one gate.
- **Already asking:** plan approval (`dispatch.redraw`, settled by approve/reject), gates (`gateDraw`/`approveGate`), the setup/init checklist (`run:<kind>`, commands/agentrun), init's safety settings (`init:5`), sync add (`initPropose(h, stage, diff, {title, lines, sub, change})`, settled by `initConfirm`/cancel), every flag (`events.emit` on `flag.raised`, settled on `flag.resolved`; a phase that asks first under `flag:<task>:<flag>`, as `tdd.specChange` does, keeps its richer card), release (`integrate.propose`, settled by the release).
- **Adding a kind** = one `ask` and one `settle` in the phase, plus the command the option runs. `tests/card.test.ts` proves it with a made-up `deploy` kind (card, band row, queue, press) and zero UI code.
- **Survives /clear:** decisions live on the board, so `core/session.rehydrate` re-asks what durable state says is owed: a draft plan (`redraw`) or an open gate (`gateDraw`, first: it shares the approval slot), spec_change tasks (from `cadre.blocked`/`cadre.specChange` in beads, with the reason), plan-level flags (from the pointer), git flags (`cadre.git`), and a landed epic's release (`integrate.propose`). Pending init/setup/sync-add proposals are **dropped** (their code and diff are per session): run the command again. Other task flags are not durable, so they are not re-asked.
