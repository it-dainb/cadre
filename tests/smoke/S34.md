# S34: `{result}` + `context` on `TaskCreate` reaches main

- **Assumption / source:** A16
- **Mode:** headless
- **Design:** DESIGN §14 (live smoke list)

## Purpose

`{result}` + `context` on `TaskCreate` reaches main.

## Steps

Headless runs go through the harness only (Docker, user directive):

```bash
R=$(git rev-parse --show-toplevel)   # repo root
RUN="env SPIKE=$R OUT=/tmp/cadre-smoke/out WORK=/tmp/cadre-smoke/work $R/harness/run.sh"   # plugin = /work/spike in the container
mkdir -p /tmp/cadre-smoke/out /tmp/cadre-smoke/work
```

```bash
$RUN -p 'TaskCreate a task with subject "x" and quote any plan rules you were given.' --plugin-dir /work/spike --model haiku --debug-file /out/S34.log
```

## Expected

The `{result}` context (plan rules, `missing:` line) appears as an attachment on main.

## M0 status

PASS. ADR 0001 S34.

## Result (live, 2026-10-10)

Harness `harness/run.sh` (Docker, pin 2.1.295, haiku). PASS. `TaskCreate {kind:"plan"}` in a repo without an approved epic: the `{result}` + `context` (`cadre plan rules (v1)` … `missing: tasks`) reached main as `tool.call hook additional context` and the model quoted it verbatim. Evidence `docs/evidence/live/b34.debug.log.gz`. (With an approved epic on the board the call is refused: `plan p-p1 is still approved`.)
