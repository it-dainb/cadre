# S48: A `--resume`-restored `/goal` is detectable

- **Assumption / source:** A27
- **Mode:** headless + interactive
- **Design:** DESIGN §14 (live smoke list)

## Purpose

A `--resume`-restored `/goal` is detectable.

## Steps

Headless runs go through the harness only (Docker, user directive):

```bash
R=~/research/claude-dgtx
RUN="env SPIKE=$R/cadre OUT=/tmp/cadre-smoke/out WORK=/tmp/cadre-smoke/work $R/harness/run.sh"   # plugin = /work/spike in the container
mkdir -p /tmp/cadre-smoke/out /tmp/cadre-smoke/work
```

1. `$RUN -p '/goal x' …`, then `$RUN -p … --resume <id>`; check `command.run`/`prompt.attachment`.
2. Interactive: type `/goal x` in a TUI; look for `command.run {command:"goal"}`.

## Expected

Headless: `/goal` arrives as `prompt.submit` text, restored goal invisible. Interactive: expect a `command.run` line.

## M0 status

FAIL (restored goal undetectable). Fallback: README warning + band hint; interactive part PENDING-HUMAN. ADR 0001 S48.
